# `icrt_multitask` dataset config

Versioned here because the live dataset lives in **`/dev/shm/icrt_multitask` on
`zeux`, which is tmpfs and does not survive a reboot.** The 18 GB hdf5 is
regenerated by `aiworker_icrt.convert_lerobot_icrt`; these small files are not,
so they are kept in git.

## `task_grouping.json`

Per-task sampling weights. `rebalance_tasks` equalises the *number of episodes*
per task, never frames, and our `ylw2` episodes average 958 frames against ~330
for the other two — so equal episode counts meant 58.9% of every epoch was the
one task where the left arm never moves.

The ratio multiplies that task's rebalance length (`dataset.py:391`):

```
rebalance_length 37  x  0.28  ->  10 ylw2 episodes per epoch
```

**Measured after applying it**, by counting `SequenceDataset.steps` on the train
split of `runs/mt21_gpu`:

```
          before    after
ylw2      58.9%     28.3%      <- left arm frozen in all of these
ecu       21.1%     36.7%
box       20.1%     35.0%
```

Every task must be listed in `tasks`, including ones at ratio 1.0 — the loader
does `self.upweight_tasks[v]` with no default and raises `KeyError` otherwise.

Wire it up by adding to `dataset_config.json`:

```json
"task_grouping": "/dev/shm/icrt_multitask/task_grouping.json"
```

The loader confirms it on startup:

```
Each task is rebalanced to have length:  37
overriding with known ratio:  {'pick_bin': 0.28, 'pick_place_left': 1.0}
```

Rationale and the options that were rejected: `../../task_balance_fix.md`.
